你不點，什麼都不動

沒有「一鍵清理」按鈕，也沒有哪個進度條替你決定什麼可以刪。

  1. 估算

    先看清每一項到底佔多少

    所有可清理目錄都在背景先估一遍，跑完再重新估。缺指令列工具的任務 會變灰；某個工具鏈的那一行只在它的快取目錄真的存在時才出現。

  2. 確認

    讀清楚具體路徑，再勾

    每一行的 ⓘ 按鈕會列出這個任務要碰的確切路徑和指令。 確認視窗會明確寫出你這次勾的哪些可還原、哪些不可還原。

  3. 回收

    進垃圾桶，留一條退路

    檔案型清理會進垃圾桶並留下還原點。頁尾報告實際釋出了多少， 可折疊的主控台把整次執行即時印出來。

佔得最多的目錄，恰好是你從來不看的那幾個。

二十二個目標，全都是可重建的。

開發快取

Xcode 的 DerivedData、Archives、Products 和舊的 iOS DeviceSupport； CocoaPods；npm、yarn、pip、SwiftPM、Gradle 快取；pnpm store； Cargo 的 registry；Go 的建置與模組快取；Maven 本機倉庫。 另外兩個掃描器專門找長期沒動的 node_modules 目錄， 以及還堆在「下載」資料夾裡的安裝檔。

~/Library/Developer/Xcode/DerivedData
◍

系統與殘留

使用者層級的快取與記錄、Homebrew 與 Ruby gem 清理、Docker 的懸空 image、建置快取、已停止的容器和沒有掛載的 volume、垃圾桶本身—— 還有一個 App 清理頁，按 Bundle ID 找出移除掉的 App 留下了什麼。

~/Library/Caches · ~/Library/Logs · ~/.Trash

一個維護主控台，不是一個魔法按鈕。

它要做的每件事，做之前都看得見；做過的每件事，做完都有記錄。

體積估算

逐項顯示目前佔用，在主執行緒之外計算，每次跑完重新刷新， 所以數字不會過期。

逐項細節

每一行一個彈出層，寫明確切的路徑或指令。任務不會做任何 彈出層裡沒告訴你的事。

即時執行記錄

主控台面板預設折疊、執行時自動展開，每移動一個檔案就印一行。

還原記錄

最多保留二十批「原路徑 → 垃圾桶路徑」的對應， 檔案還在垃圾桶裡時一鍵還原。

它把檔案移到垃圾桶，不是刪掉。

檔案型清理一律經垃圾桶並寫入還原點，所以手一抖的代價是點一下， 而不是一個下午。Cruft 不安裝任何特權 helper——受保護的 App 會被回報為 失敗，而不是繞過去提權。清理目標只在你自己擁有的位置，絕不碰 /Library 或 /System。指令型任務、清空垃圾桶 和 Docker prune 是例外，執行前 App 會明說。
